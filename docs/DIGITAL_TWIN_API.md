# FIREWISE Digital Twin — API

The API follows the FIREWISE conventions:
- JSON request and response bodies; Pydantic validation.
- Validation failures return `422 {error:{code:"validation_error", message, details:{errors:[{loc,msg,type}]}}}`.
- Invalid references (unknown zone or slot, wrong environment) return `400 invalid_parameter`.
- An unknown or foreign id returns `404 not_found`.
- A missing scientific database returns `503 unavailable`.

Calculations are deterministic and server-side; the language model never computes scientific values or counts.

**Workspace header.** Routes marked 🔑 require `X-Workspace: <32–128 chars of A-Z a-z 0-9 _ ->`. That is a random key generated by the client. Data is visible only to the workspace that created it.

## Environments, models, validation
| Method | Route | Purpose |
|---|---|---|
| GET | `/api/twin/environments` | Habitat templates (geometry, zones, experiment slots, monitoring points, equipment) |
| GET | `/api/twin/environments/{env_id}` | One template |
| GET | `/api/twin/environments/{env_id}/presets` | Starting scenarios (sea-level cabin air; exploration atmosphere; Moon-base challenge definition), each value user-defined with a source note |
| GET | `/api/twin/models?include_planned=true` | Model cards: equations, inputs/outputs with units and ranges, assumptions, boundary conditions, applicability, validation status, limitations, references; planned models listed as `not_implemented` |
| GET | `/api/twin/models/{model_id}` | One model card |
| GET | `/api/twin/validation[?model_id=]` | Verification/validation records with MAE, RMSE, bias and relative error |

| GET 🔑 | `/api/twin/simulations/{run_id}` | Run status and results |

### Evidence semantics
- Only non-duplicate combustion/aerosol records are considered.
- Chamber (ambient) O₂ only. Burner-stream O₂ is never compared with a cabin.
- Airflow is compared only for ambient flow types: forced duct, quiescent, coflow and imposed envelope.
- Temperature is never documented in PSI tables.
- An exact match needs every enabled variable documented and within tolerance, at the same gravity.
- Nearest records are ranked by (number of variables compared, descending), then D = √Σ((x − target)/tolerance)², then row key. An undocumented variable never contributes a distance.

### Physics result shape
`{model_id, model_name, model_version, scope, status: completed|unavailable|rejected, reason, inputs:[{name,value,unit,status,source}], outputs:[{name,value,unit,status:"simulated",validation_status}], assumptions, limitations, warnings, validation_status}`

The response also carries `engine_version`, `input_hash`, `geometry`, `planned_models` and `notice`.

## Copilot
| Method | Route | Purpose |
|---|---|---|
| POST | `/api/ask` | Body `{question, scenario_id?, twin?: {scenario, selected_zone?, scenario_id?}}` → `AskResponse` with `cached: bool`. With `twin`, answers use the scenario, its evidence, physics results, model cards and validation records |
| GET 🔑 | `/api/conversations[?kind=general\|twin]` | Saved conversations, most recent first |
| POST 🔑 | `/api/conversations` | Body `{title?, kind}` → new conversation |

| PATCH 🔑 | `/api/conversations/{id}` | Rename `{title}` |
| DELETE 🔑 | `/api/conversations/{id}` | Delete (204) |
| POST 🔑 | `/api/conversations/{id}/messages` | Body `{question, twin?}`: asks, stores the exchange, auto-titles from the first question |

### Claim tiers
| Tier | Meaning |
|---|---|
| `measured` | NASA records and SQL counts |
| `reported` | NASA text |
| `literature` | Published sources outside PSI |
| `calculation` | Exact physical-law arithmetic |
| `model_prediction` | Correlation-based estimate |
| `unknown` | Not documented or not computable |
| `interpretation` | Hedged reasoning or hypothesis |

### Validator rules
- A claim is removed if:
  - a citation is unknown
  - a number does not appear in the cited evidence
  - a calculation or prediction claim has no model or calculation citation
  - it makes a fire-behaviour prediction, a partial-gravity prediction or a risk statement
- A `measured` claim without NASA or SQL evidence is downgraded to `reported`.

### Answer cache
The cache key covers:
- the normalised question
- the whole twin context, plus the workspace for twin questions
- the database build fingerprint
- the answer mode and model
- the engine version

Answers produced because the language model failed are never cached. Entries expire after 30 days, and at most 5000 are kept.
